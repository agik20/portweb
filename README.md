# Portweb — Personal Web Portfolio

A minimal, fast portfolio website built with plain HTML and Tailwind CSS. No frameworks, no fluff. Just ship your work.

> If you’re looking for a simple repo you can clone, edit, and deploy in minutes, this is it.

---

## Tech Stack

* **HTML** for structure
* **Tailwind CSS** (via CLI) for styling
* Optional: **Live Server** (VS Code extension) or any static file server for local preview

---

## Project Structure

```
portweb/
├─ dist/                 # Compiled CSS output (generated by Tailwind)
├─ node_modules/         # Dependencies
├─ src/                  # Source files (HTML snippets, CSS input, assets)
│  └─ styles/
│     └─ input.css       # Tailwind entry with @tailwind directives
├─ index.html            # Main page
├─ tailwind.config.js    # Tailwind config (content paths, theme, plugins)
├─ package.json          # Scripts and dev deps
└─ package-lock.json
```

> If your tree differs, keep the idea: edit files in `src/`, generate CSS to `dist/`, link it in `index.html`.

## Getting Started

### 1) Prerequisites

* **Node.js 18+** and **npm** installed.

### 2) Clone the repo

```bash
git clone https://github.com/agik20/portweb.git
cd portweb
```

### 3) Install dependencies

```bash
npm install
```

### 4) Start development (watch Tailwind)

```bash
npm run dev
```

This will run the Tailwind CLI in watch mode and write the compiled CSS to `dist/`. Open `index.html` in your browser (or use a static server like VS Code **Live Server**).

### 5) Build for production (minified CSS)

```bash
npm run build
```

The output CSS in `dist/` will be minified and ready to deploy.

## Tailwind CSS Initialization (Step‑by‑Step)

> Use this if you want to reinitialize Tailwind from scratch or replicate the setup elsewhere.

1. **Initialize npm** (if you’re starting in a fresh folder)

   ```bash
   npm init -y
   ```

2. **Install Tailwind + PostCSS + Autoprefixer**

   ```bash
   npm install -D tailwindcss postcss autoprefixer
   ```

3. **Create Tailwind & PostCSS configs**

   ```bash
   npx tailwindcss init -p
   ```

   This generates:

   * `tailwind.config.js`
   * `postcss.config.js`

4. **Configure content paths** in `tailwind.config.js` so Tailwind can purge unused styles:

   ```js
   // tailwind.config.js
   export default {
     content: [
       "./index.html",
       "./src/**/*.{html,js,ts,jsx,tsx}"
     ],
     theme: { extend: {} },
     plugins: [],
   }
   ```

5. **Create your CSS entry file** (e.g., `src/styles/input.css`) with Tailwind directives:

   ```css
   /* src/styles/input.css */
   @tailwind base;
   @tailwind components;
   @tailwind utilities;
   ```

6. **Add npm scripts** to compile Tailwind (adjust paths to match your project):

   ```json
   // package.json (scripts)
   {
     "scripts": {
       "dev": "npx tailwindcss -i ./src/styles/input.css -o ./dist/styles.css --watch",
       "build": "npx tailwindcss -i ./src/styles/input.css -o ./dist/styles.css --minify"
     }
   }
   ```

7. **Link the compiled CSS** in `index.html`:

   ```html
   <!-- in index.html -->
   <link rel="stylesheet" href="./dist/styles.css" />
   ```

8. **Run in development** and start editing:

   ```bash
   npm run dev
   ```

   Tailwind will watch your files and rebuild CSS on save.

> Analogy: Tailwind is your parts bin; `src/styles/input.css` is the assembly line; `dist/styles.css` is the finished component you actually bolt onto the page.

## Available Scripts

These are typical scripts used in this repo. Check your `package.json` in case you’ve customized paths.

```json
{
  "scripts": {
    "dev": "npx tailwindcss -i ./src/styles/input.css -o ./dist/styles.css --watch",
    "build": "npx tailwindcss -i ./src/styles/input.css -o ./dist/styles.css --minify",
    "serve": "npx http-server . -p 5173 -c-1" // optional local server
  }
}
```

* `dev`: Watches files and rebuilds CSS on change.
* `build`: Produces a minified CSS bundle for production.
* `serve` (optional): Serves the folder at `http://localhost:5173/`.

## Customization Tips

* **Colors/Fonts:** Extend the theme in `tailwind.config.js` under `theme.extend`.
* **Components:** Create small, reusable HTML snippets and use Tailwind’s `@apply` in a separate CSS file if you want to abstract repetitive classlists.
* **Icons:** Use any icon set (Heroicons, Lucide, etc.).

## Deployment

Any static host works. Two quick options:

### GitHub Pages (root)

1. Ensure `index.html` references `./dist/styles.css`.
2. Push to `main` (or `gh-pages` branch if you prefer dedicated pages).
3. In GitHub → **Settings** → **Pages** → **Source**: select the branch and root.

### Netlify / Vercel

* Set build command to `npm run build` (optional if you just commit `dist/`).
* Publish directory can be the repo root or a subfolder depending on your setup. Since it’s static HTML, you can also deploy directly without a build step.

## Notes

* Keep assets small and lazy‑load heavy images.
* Audit CSS size occasionally; if it grows unexpectedly, double‑check `content` globs in `tailwind.config.js`.
* If styles don’t show up, **99%** of the time the CSS path in `index.html` is wrong or the Tailwind watcher isn’t running.
